# Bitácora del monitor

- Primer incremento: cuatro recorridos desde artefactos cerrados; ruta React aislada y exportador sin ejecución del harness. La inspección HNP-01 y sus imports compartidos corresponde al corte histórico del 18 de octubre de 2026.
- MON-02A: corrige confirmación atribuida a operaciones bloqueadas/no iniciadas, separa creación y recuperación y expone budget pass del validador como discrepante del deny backend. 43 tests en ese corte; originales preservados.
- MON-02B: agrega fixture HTTP local fija, integridad, contrato, límites, rechazo de métodos y estados de fuente explícitos. 69 tests distintos acumulados; no se suman repeticiones ni tests históricos HNP.
- Preparación de publicación 19 de octubre de 2026: documentación portable, copia publicable de los ocho tests herméticos de navegación y del preview con API bloqueada. Atributos limitados a rutas del monitor evitan conversión de bytes y mantienen verificable su manifiesto en clones Windows. No se cambia la semántica de los cuatro recorridos ni el runtime comercial.
- Endurecimiento previo a la fusión (19 de octubre de 2026): `npm run test` hermético y en CI; `/governance` solo en builds con `VITE_GOVERNANCE_MONITOR=true` y tras la misma sesión Better Auth que la app; el exportador emite v2 y la UI ya no traduce v1; la etiqueta HP dice «creación observada» salvo un allow D1 aplicado (id `hp-created`); los textos del validador dependen de `executionKind`; los avisos PARTIAL salen de `gates.ts`; puerto, orígenes y directorio de la demo se configuran por entorno en `demo-config.ts`. 82 tests distintos (74 Node + 8 Python). Los originales de `sources/` no cambian.
- Proyección HNP-02 (20 de octubre de 2026): contrato `governance-monitor/3` con esquema JSON compartido; los cuatro escenarios no cambian de significado y se añade `experiments`. Se incluye la corrida dry-run `hnp02-dry_run-20261020T044329Z-s20261022` (FakeTransport, dos repeticiones, cero llamadas al proveedor) en una vista propia con avisos obligatorios de entorno ficticio y transporte simulado; `llm validator dry-run` y `llm validator provider` tienen textos e invariantes propios y no relajan la regla HNP de los escenarios. El snapshot de demostración solo admite experimentos dry-run y cambia su hash; `provenance.json` se escribe con los mismos bytes en cualquier plataforma. 110 tests distintos (87 Node + 23 Python).
- Limpieza (20 de octubre de 2026): `npm run governance:demo` reemplaza el lanzador PowerShell y levanta también Better Auth; la caché pasa a `.local/governance-demo`. Se retiran `PUBLICATION-SHA256SUMS` y los `.gitattributes` por directorio; la raíz conserva solo los bytes con hash (`sources/` y `evidence.json`). HANDOFF-YAIR.md y RESULTS.md se fusionan en el README. El bundle y el snapshot no cambian; el test de configuración solo actualiza el directorio por defecto.
- Retiro (20 de octubre de 2026): se borran el visor `/governance`, sus historias, los tests de Node y de Python, el E2E, el lanzador `npm run governance:demo`, el servidor de snapshots, el exportador, la proyección `evidence.json`, el esquema `governance-monitor-3.schema.json` y la variable `VITE_GOVERNANCE_MONITOR`. Lo reemplaza la traza de compras ([docs/design/trace-panel.md](../design/trace-panel.md)). Se conservan sin cambios `sources/`, `provenance.json`, el inventario HNP-01 y esta bitácora; `tests/contracts/test_governance_evidence_hashes.py` comprueba cada fuente contra `provenance.json` sin el exportador. El README pasa a describir la evidencia, no el visor.

Los archivos locales de auditoría, paquetes y logs no se incorporan. Se excluyen del PR las notas antiguas de costos HNP-02, inspección remota y el verificador de custodia dependiente de rutas de un equipo; se conservan localmente. Lo pendiente de HNP-02 con proveedor se resume en «Límites» del [README](README.md), sin habilitar proveedores; la lectura autenticada que proponía MON-02C la retoma la traza de compras. Ningún corte cierra PARTIAL ni AUDIT-MERCHANT-CANCEL-01.
